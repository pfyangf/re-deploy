## Context

当前 re-deploy 系统后端已提供 Agent 二进制下载接口（`/api/agent/download/{os}/{arch}`），但前端 UI 中没有任何 Agent 下载或安装引导的入口。用户添加新服务器时，需要先在目标机器上安装 Agent，但只能手动拼接下载 URL 或查阅外部文档，流程不闭环。

服务器管理页面采用 Vue 3 + Element Plus 构建，前端源码为编译后的单文件 JS（`server/src/main/resources/static/assets/index-*.js`）。修改需在前端源码中完成后重新构建。

## Goals / Non-Goals

**Goals:**
- 在服务器管理页面工具栏增加"下载 Agent"按钮
- 提供 Agent 安装指南弹窗，包含下载、配置、Token 获取三步完整指引
- 命令中的 server 地址自动拼接当前页面 origin，用户复制即用
- 弹窗底部提供"去添加服务器"快捷入口，形成流程闭环

**Non-Goals:**
- 不提供 Windows 版本 Agent 的安装指引（仅 Linux amd64/arm64）
- 不修改后端下载接口（已存在且可用）
- 不提供一键安装脚本（用户明确不需要）
- 不修改 agent 端代码
- 不涉及数据库变更

## Decisions

### 1. 按钮位置：工具栏右侧，"添加服务器"左侧
- **选择**：服务器管理页面顶部工具栏，"添加服务器"按钮左边放置"下载 Agent"按钮
- **理由**：用户添加新服务器前的自然操作顺序是"先装 Agent，再加服务器"，按钮并列放置符合使用流程
- **备选**：放在页面其他位置或侧边栏 → 关联性弱，用户不容易找到

### 2. 弹窗结构：三步式 + 参考信息
- **选择**：按"下载 → 配置服务 → 获取 Token"三步组织，下方附常用命令和目录结构
- **理由**：符合用户实际操作顺序，步骤清晰，新手友好
- **备选**：纯下拉菜单直接下载二进制 → 用户下载后不知道怎么装，仍需查文档

### 3. Server URL 自动拼接
- **选择**：使用 `window.location.origin` 动态生成下载 URL
- **理由**：用户无需手动修改地址，复制命令即可直接执行，降低出错概率
- **备选**：让用户手动填写 server 地址 → 增加操作步骤和出错可能

### 4. 架构切换：单选按钮组
- **选择**：amd64 / arm64 单选，默认 amd64
- **理由**：服务器场景 amd64 占绝大多数，同时兼顾 arm64 需求
- **备选**：下拉菜单 → 选项少，单选按钮更直观

### 5. 复制按钮
- **选择**：每个代码块右上角提供"复制"按钮
- **理由**：命令行操作场景下复制是最高频操作，减少用户手动选中的麻烦
- **备选**：无复制按钮，用户手动选中 → 体验差

### 6. "去添加服务器"快捷跳转
- **选择**：弹窗底部放置"去添加服务器"按钮，点击后关闭指南并打开添加服务器对话框
- **理由**：安装完 Agent 后的下一步就是添加服务器，形成完整流程闭环
- **备选**：只有关闭按钮 → 用户需要手动再点"添加服务器"，多一步操作

## Risks / Trade-offs

- [风险] 前端是编译产物，源码可能不在仓库中 → 需要找到前端源码位置或确认构建方式
- [权衡] 弹窗信息较多可能显得拥挤 → 按步骤分区展示，用标题分隔，视觉上有层次感
- [限制] 仅支持 Linux → 符合用户明确需求，Windows 用户暂不考虑
