## Context

部署操作页面（`frontend/src/views/Deploy.vue`）当前每次部署都需要手动选择任务、服务器、填写版本号和 Jenkins 构建号。对于重复部署相同配置的场景，用户体验不佳。

本功能完全在前端实现，使用浏览器 localStorage 存储历史记录，不涉及后端、API 或数据库变更。

## Goals / Non-Goals

**Goals:**
- 用户点击部署后自动缓存表单参数到 localStorage
- 选择任务后展示该任务最近 3 次部署记录
- 点击历史记录一键回填所有表单字段
- 按 taskId 分组，每任务最多保留 3 条

**Non-Goals:**
- 不涉及服务端存储或同步
- 不跨设备同步（仅本地浏览器）
- 不提供历史记录管理（删除、重命名等），满了自动淘汰最旧
- 不缓存分组选择器（selectedGroupId），只缓存实际提交的表单字段

## Decisions

### 1. 存储结构

使用单一 localStorage key，值为 JSON 对象，按 taskId 分组：

```javascript
// localStorage key: "redeploy_deploy_history"
{
  "1": [
    {
      taskId: 1,
      taskName: "web-portal-deploy",
      serverIds: [1, 2, 3],
      version: "v1.2.0",
      jenkinsBuildNumber: "164",
      timestamp: 1712345678000
    },
    // ... 最多 3 条
  ],
  "2": [
    // ...
  ]
}
```

**备选方案**：每条记录存一个 key（如 `redeploy_history_1_0`）—— 不选，因为读写和维护更繁琐，单 key JSON 更简洁。

**为什么存 taskName**：展示时需要任务名称，虽然可以从 tasks 列表里查，但存一份更方便且不占多少空间。

### 2. 保存时机：点击部署即存（不论成功失败）

在 `handleSubmit()` 函数中、API 调用之前执行保存。

**理由**：
- 失败场景也需要快速重试（这正是快捷填充的高频使用场景）
- 参数经过了前端校验，有效性有保障
- 不需要等待异步结果，实现更简单

### 3. 去重策略：完全相同参数只更新时间戳

新记录入队前，检查是否已存在参数完全相同的记录。如果存在，将其移到队首并更新时间戳，不新增。

相同判定：taskId、serverIds（排序后比较）、version、jenkinsBuildNumber 全部相同。

**理由**：避免连续部署相同参数产生无意义的重复记录，浪费有限的 3 条名额。

### 4. UI 位置：表单顶部独立区域

在 `el-card` 内部、表单顶部添加一个「快捷填充」区域。使用横向排列的卡片式条目，悬停可点击。

```
┌─────────────────────────────────────────┐
│  快捷填充（最近 3 次部署）               │
│  ┌──────┐ ┌──────┐ ┌──────┐            │
│  │v1.2.0│ │v1.1.0│ │v1.0.0│            │
│  │3 台  │ │2 台  │ │3 台  │            │
│  │2小时前│ │昨天  │ │3天前 │            │
│  └──────┘ └──────┘ └──────┘            │
├─────────────────────────────────────────┤
│  部署表单...                            │
└─────────────────────────────────────────┘
```

**备选方案**：下拉选择器 —— 不选，因为卡片式更直观，一眼能看到所有选项。

### 5. 回填逻辑

点击记录后，直接将记录中的字段赋值给 `form.value` 对应字段即可。Vue 的响应式会自动更新 UI。

需要注意：`serverIds` 是数字数组，回填时直接赋值即可，Element Plus 的 checkbox-group 会自动匹配。

## Risks / Trade-offs

- **[Risk] localStorage 容量限制** → 数据量极小（每任务 3 条，几十字节），完全不构成问题
- **[Risk] 服务器被删除后回填显示异常** → serverIds 对应不上的服务器在 checkbox 中不会被勾选（因为 el-option 不存在），表现为静默丢失选择，可接受。用户能看到哪些被选中了
- **[Trade-off] 点击即存 vs 成功才存** → 选择点击即存，牺牲「记录都是成功部署」的保证，换取失败重试的便利
- **[Trade-off] 存 taskName 冗余** → 存副本更简单，缺点是任务改名后历史记录显示旧名称；可接受，3 条记录很快会被刷新
