## Context

当前部署操作页面（/deploy）的交互是：页面加载时一次性拉取所有任务和所有服务器，服务器按分折叠展示。Jenkins 构建号需要用户手动输入。随着分组、任务、服务器数量增加，查找效率降低，手动输入构建号也容易出错。

后端 API 已支持按 `groupId` 过滤任务（`GET /api/tasks?groupId=`）和服务器（`GET /api/servers?groupId=`），但前端部署页没有利用这个能力。

Jenkins 集成目前只有部署时下载构建产物的能力，没有查询构建历史的接口。

## Goals / Non-Goals

**Goals:**
- 部署页支持按分组快速筛选任务和服务器，减少查找时间
- Jenkins 构建号支持从构建历史列表中选择，降低手动输入错误
- 完全向后兼容，不破坏现有部署流程

**Non-Goals:**
- 不做 Jenkins 配置独立管理（留待后续变更）
- 不做 Jenkins 配置页面
- 不改动任务创建/编辑流程
- 不改动部署执行逻辑
- 不做多选分组（仅单选 + 全部）

## Decisions

### 1. 分组筛选：单选下拉 + 「全部分组」默认值

**决策**：部署页顶部增加一个分组下拉选择器，选项包括「全部分组」+ 所有分组。默认选中「全部分组」，行为与现状一致。

**理由**：
- 单选足够覆盖绝大多数场景（部署操作通常针对一个业务线/环境）
- 「全部」兜底，不丢失现有能力
- 实现简单，交互清晰

**备选方案**：
- 多选 tag 式：灵活但交互复杂，且后端 API 暂不支持多 groupId 查询
- 默认选中上次使用的分组：体验更好但需要持久化状态，初期没必要

### 2. 切换分组时清空已选任务和服务器

**决策**：用户切换分组时，清空已选中的任务和服务器。

**理由**：
- 避免出现"选了 A 分组的任务但当前显示 B 分组"的不一致状态
- 简单明确，不易出错

**备选方案**：
- 保留选择但置灰：技术上可行但增加复杂度，收益不大

### 3. 服务器列表显示模式

**决策**：选中「全部分组」时，服务器按分组折叠展示（现有行为）；选中单个分组时，服务器平铺展示（不折叠）。

**理由**：
- 单分组下折叠没有意义，反而多一步点击
- 全部分组下折叠仍然有价值，避免列表过长

### 4. 构建历史查询走后端代理

**决策**：新增后端 API `GET /api/deploy/jenkins/builds?taskId=xxx`，后端通过任务的 Jenkins 配置调用 Jenkins JSON API，返回构建列表。前端不直接连接 Jenkins。

**理由**：
- 安全：Jenkins Token 不暴露给前端
- 网络：Jenkins 可能在内网，前端浏览器不一定能直连
- 统一鉴权：复用现有的 admin-token 认证机制

**备选方案**：
- 前端直连 Jenkins：少一跳但 Token 泄露风险高，且可能有跨域问题

### 5. 构建历史 API 放在 DeployController 下

**决策**：构建历史查询接口挂在 `DeployController` 下，路径 `/api/deploy/jenkins/builds`。

**理由**：
- 这是部署场景的辅助功能，和部署强相关
- 目前 Jenkins 配置在任务级别，按 taskId 查询最自然
- 后续如果做 Jenkins 配置独立管理，可以迁移到独立的 JenkinsController

### 6. 构建号交互：输入框 + 右侧「拉取」按钮

**决策**：构建号仍保留输入框形态，右侧增加「拉取」按钮；点击按钮弹出构建历史下拉面板，点击某条自动填入输入框。

**理由**：
- 保留手动输入的灵活性（有时需要输入列表外的老构建号）
- 按钮触发请求，避免页面加载时不必要的 Jenkins 调用
- 交互模式常见，用户容易理解

**备选方案**：
- 纯下拉选择框（el-select）：不支持手动输入任意值，灵活性差
- 可搜索下拉（el-select filterable + remote）：可以实现但交互较重，按钮触发更明确

### 7. 构建历史列表展示内容

**决策**：列表展示构建号、状态（成功/失败/进行中）、构建时间、描述（如有），按构建号倒序（最新在最上），默认返回最近 20 条。

**理由**：
- 20 条足够覆盖日常使用场景
- 状态和时间帮助用户快速识别要选的构建
- 全部展示（含失败），不做默认过滤，用户自己判断

## Risks / Trade-offs

| 风险 | 影响 | 缓解措施 |
|------|------|----------|
| Jenkins 不可达时构建历史查询失败 | 用户无法通过列表选择，需手动输入 | 接口返回友好错误提示，输入框仍可手动输入 |
| Jenkins 构建历史很多时查询慢 | 前端等待时间长 | 限制返回条数（默认 20），后端设置超时（5s） |
| 切换分组时清空选择可能让用户困扰 | 操作体验不连贯 | 切换时给出轻量提示？或者干脆不清空只过滤——但实现更复杂 |
| Token 存储在后端，多人共用同一部署系统 | 一个用户的 Jenkins 配置对所有管理员可见 | 目前 admin-token 是全局的，本身就是单用户系统，暂不处理 |

## Migration Plan

- 纯增量改动，无数据迁移
- 前端构建后替换静态资源即可
- 后端重新打包部署即可
- 回滚：回退到上一版本 jar 和前端静态资源

## Open Questions

- 构建历史列表是否需要「只看成功构建」的筛选开关？（初期不加，后续根据使用反馈决定）
- 切换分组时是否需要保留已选项并给出提示？（初期直接清空，简单直接）
